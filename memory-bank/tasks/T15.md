# T15: VaultScanner Rewrite for Hidden/Dot Folder Access

*Created: 2026-08-19*
*Status: 🔄 ACTIVE*
*Priority: P1*

## Objective

Rewrite the `VaultScanner` to allow selective access to hidden and dot folders (e.g., `.obsidian/plugins/obsidian-ai/sessions/`) that are currently excluded by the `.obsidian/` pattern. This enables SyncIt to sync plugin data that lives inside `.obsidian/` while maintaining safety boundaries.

## Background

SyncIt currently uses `app.vault.getFiles()` which only returns Obsidian-tracked files in the vault root. The `.obsidian/` directory is excluded by default to avoid syncing plugin code, settings, and caches. However, this also prevents syncing valuable data like chat sessions stored in `.obsidian/plugins/obsidian-ai/`.

## Scope

### In Scope
- Add `includePatterns` setting (whitelist exceptions to `excludePatterns`)
- Rewrite `VaultScanner.scan()` to use `app.vault.adapter.list()` for hidden paths
- Safety blocklist for dangerous files (`.js`, `.css`, `manifest.json`, `data.json`)
- Support for single-folder whitelisting (e.g., `.obsidian/plugins/obsidian-ai/sessions/`)

### Out of Scope
- Full `.obsidian/` sync (too dangerous)
- Plugin code syncing
- Settings file syncing

## Implementation Plan

### Phase 1: Scanner Architecture
- Create `HiddenPathScanner` class using `app.vault.adapter.list()`
- Merge results with existing `VaultScanner` output
- Add `includePatterns` to `SyncItSettings`

### Phase 2: Safety Boundaries
- Hardcoded blocklist for executable/config files
- Validate include paths don't escape `.obsidian/`
- Warn user when adding include patterns

### Phase 3: Testing
- Test with obsidian-ai sessions folder
- Verify exclusion still works for `.obsidian/` generally
- Test safety blocklist prevents dangerous syncs
