## Research Findings

### Remotely Save (fyears)
- **Version**: 0.5.25 (last updated ~2 years ago)
- **Backends**: WebDAV, S3, Dropbox, OneDrive, Google Drive, Box, pCloud, Yandex, Koofr, Azure, Webdis
- **Architecture**: Abstract `FakeFs` interface with per-backend implementations
- **Sync**: Complex algorithm with conflict resolution, encryption layer, local DB for metadata
- **Key files**: `fsWebdav.ts`, `fsAll.ts`, `baseTypes.ts`, `main.ts`, `sync/` (pro version)
- **WebDAV specifics**: Uses `webdav` npm package, patches `request` to use Obsidian's `requestUrl`, supports chunked uploads for Nextcloud/Apache/SabreDAV, handles depth=1 vs infinity PROPFIND
- **Size**: ~5000+ lines of sync logic

### LiveSync (vrtmrz)
- **Backend**: CouchDB/PouchDB
- **Architecture**: Real-time replication, end-to-end encryption, P2P sync
- **Complexity**: Very high — handles conflicts, revisions, chunking, encryption
- **Size**: Massive codebase, 100+ files

### obsidian-ai (our own)
- **WebDAV adapter**: `src/sync/WebDAVStorageAdapter.ts` — ~250 lines
- **Uses**: `requestUrl` from obsidian directly (no external HTTP lib)
- **Features**: Basic auth, PROPFIND parsing, MKCOL, PUT, GET, DELETE
- **Proven**: Works for session sync in production

## Key Decisions

1. **Standalone plugin** — Not folded into obsidian-ai
2. **WebDAV-only MVP** — No S3/Dropbox/etc. in v1
3. **Manual sync** — Button-triggered, not real-time or auto-sync
4. **Timestamp comparison** — Newer wins, simple conflict resolution
5. **No encryption layer** — Rely on HTTPS + obsidian-secrets if needed
6. **No local DB** — Use Obsidian's `app.vault` metadata directly
7. **Exclude patterns** — `.obsidian/`, `.git/`, attachments by default
