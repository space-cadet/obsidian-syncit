# T12d: Local Sync Index — Skip Unchanged Files

**Status**: 📋 Planned
**Priority**: P1
**Parent**: T12
**Created**: 2026-08-17

## Problem

Every sync run re-reads every local file and re-compares it against every remote file. For a vault with 500 files where only 3 changed, you're still doing 500 comparisons and 500 PROPFIND entries.

## Solution

Maintain a **local sync index** — a JSON file stored in the plugin's data directory (`.obsidian/plugins/obsidian-syncit/sync-index.json`) that records:

```json
{
  "lastSyncTime": 1692259200000,
  "files": {
    "Projects/Notes/foo.md": {
      "localMtime": 1692259100000,
      "remoteMtime": 1692259100000,
      "localSize": 1234,
      "remoteSize": 1234,
      "etag": "\"abc123\""
    }
  }
}
```

On sync:
1. Read local file list
2. Read remote file list
3. For each file, check index: if local mtime + size match index → skip unless remote changed
4. Only compare files that are new, modified, or not in the index

## Dependencies

- **T4 (ETag support)** — ETags are the most reliable way to detect remote changes without downloading. If T4 is not implemented, can fall back to mtime+size comparison.
- If T4 is done, use ETag as the authoritative "unchanged" signal.

## Implementation Plan

1. Add `SyncIndex` type and `SyncIndexManager` class
2. Read index at sync start, update it at sync end
3. Integrate into `buildPlan()` — skip files that match index
4. Persist index to disk ( Obsidian plugin data directory)

## Files to Modify

- `src/sync/SyncIndex.ts` — new file
- `src/sync/SyncPlan.ts` — `buildPlan()` to use index
- `src/types.ts` — add index types

## Acceptance Criteria

- [ ] Unchanged files are skipped without network round-trips
- [ ] Index is updated after successful sync
- [ ] Index is invalidated/cleared on settings change (different server, baseDir)
- [ ] Graceful degradation if index is missing or corrupted
- [ ] No stale syncs (if remote changes outside plugin, still detected)
