## Problem

Every sync run re-reads every local file and re-compares it against every remote file. For a vault with 500 files where only 3 changed, you're still doing 500 comparisons and 500 PROPFIND entries.

## Solution

Maintain a **local sync index** — a JSON file stored in the plugin's data directory (`.obsidian/plugins/obsidian-syncit/sync-index.json`) that records file state from the last successful sync.

## Implementation

### New Files
- `src/sync/SyncIndex.ts` — `SyncIndexManager` class with `IndexStorage` interface

### Modified Files
- `src/types.ts` — Added `SyncIndex`, `SyncIndexEntry`, `etag` to `FileEntity`
- `src/sync/SyncPlan.ts` — `buildPlan()` now skips index-matched files via `indexManager.isUnchanged()`
- `src/main.ts` — Loads index before sync, updates it after successful sync, clears on settings change
- `src/remote/WebDAVAdapter.ts` — Captures ETags from PROPFIND `<d:getetag/>`

## How It Works

1. **Before sync**: Load `sync-index.json`. If server signature (hash of URL+username+baseDir) doesn't match, discard it.
2. **During plan building**: For each file pair, if local mtime+size match index AND remote ETag matches index → skip (count as unchanged).
3. **After successful sync**: Re-scan local and remote files, build fresh index, save to disk.
4. **On settings change**: Index is cleared automatically.

The local index is a cache for performance, not a shared cross-device baseline. T13 adds the remote manifest and deletion tombstones needed to distinguish stale offline files from genuinely new files. The index must also remain unchanged when a sync is partial or cancelled.

## Acceptance Criteria

- [x] Unchanged files are skipped without network round-trips
- [x] Index is updated after successful sync
- [x] Index is invalidated/cleared on settings change (different server, baseDir)
- [x] Graceful degradation if index is missing or corrupted
- [x] No stale syncs — if remote changes outside plugin, ETag mismatch detects it
- [ ] Do not commit a new cache after partial or cancelled transfers
- [ ] Do not use a local-only index to resolve first-sync deletion ambiguity
