## Objective

Implement the approved SyncIt mockup as the actual product UI and make sync failures directly inspectable. The previous scroll fix is only a layout safeguard; it does not satisfy this redesign task.

## Design Reference

- Mockup: [2026-09-01 SyncIt UI scroll-owner mockup](../screenshots/2026-09-01-syncit-ui-scroll-owners.png)
- Detailed design: [`implementation-details/ui-redesign-and-observability.md`](../implementation-details/ui-redesign-and-observability.md)

## Scope

- Replace the current stacked/sidebar presentation with the approved Sync, Activity, Errors, reconciliation, and progress surfaces.
- Keep one intentional scroll owner per surface, with fixed controls outside scrollable content.
- Show sync status, direction, planned work, recent activity, and error counts in a clear hierarchy.
- Provide a proper log viewer rather than the current stylized grouped list and raw JSON detail blocks.
- Link summary error counts to individual persisted failure records.
- Validate narrow, normal, and resized Obsidian layouts on desktop and mobile.

## Subtasks

- [x] T16a: Redesign the Sync sidebar and status/action hierarchy
- [x] T16b: Redesign reconciliation as a table with fixed actions
- [x] T16c: Implement Activity and Errors as a proper log viewer
- [ ] T16d: Complete responsive, scroll, keyboard, and real-device acceptance

## Non-Goals

- Do not change the sync direction or reconciliation safety algorithm except where required to expose correct status.
- Do not treat the existing source-level overflow fix as visual acceptance.
- Do not silently discard historical logs during the viewer migration.

## Acceptance Criteria

- [x] The implemented UI matches the approved mockup’s structure, hierarchy, and action placement.
- [x] Every list that can exceed the viewport has one obvious scroll owner and exposes its final row and fixed actions.
- [x] A sync reporting hundreds of errors exposes each failure in the Errors surface.
- [ ] Activity, Errors, reconciliation, and progress states remain usable after pane resize.
- [x] Unit/build checks pass; manual Obsidian checks still need viewport evidence.
