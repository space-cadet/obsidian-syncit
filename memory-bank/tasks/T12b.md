# T12b: Parallel Sync with Concurrency Limit

**Status**: ✅ COMPLETE
**Priority**: P0 — Highest Impact
**Parent**: T12
**Created**: 2026-08-17
**Completed**: 2026-08-17

## Problem

`SyncPlanBuilder.executePlan()` processed uploads, downloads, and conflicts in three sequential `for...of` loops with `await` per iteration. For 100 files, this meant 100 sequential network round-trips (~20 seconds at 200ms each).

## Solution Implemented

1. **Added `runWithConcurrency()` helper** — runs operations with a configurable concurrency limit using a `Set<Promise>` pool + `Promise.race()` for backpressure.
2. **Applied to uploads, downloads, conflicts** — each batch runs in parallel up to the limit.
3. **Added `concurrencyLimit` setting** — user-configurable slider (1–10, default: 3).
4. **Progress reporting** — still reports per-operation completion (order may vary, but count is accurate).
5. **Cancel support** — checked between batches; in-flight operations complete but no new ones start.

## Changes

- `src/sync/SyncPlan.ts`:
  - `executePlan()` — now accepts `concurrencyLimit` parameter
  - Added `runWithConcurrency()` — concurrency limiter utility
  - Uploads, downloads, conflicts all use parallel execution

- `src/types.ts`:
  - Added `concurrencyLimit: number` to `SyncItSettings`
  - Default: `3`

- `src/settings.ts`:
  - Added "Performance" section with concurrency limit slider (1–10)

- `src/main.ts`:
  - Passes `this.settings.concurrencyLimit` to `executePlan()`
