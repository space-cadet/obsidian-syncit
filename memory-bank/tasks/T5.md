# T5: Sync History Log

*Created: 2026-08-17 14:20 IST*
*Last Updated: 2026-09-03 12:31 IST*

**Status**: 🔄 **PARTIAL — general logger and failure records implemented; dedicated operation record pending**
**Priority**: P1 (User's #2)

## Details

Persistent log of all sync operations so users can answer "what just happened?" after a sync.

## Goals

1. **Log all sync operations**: timestamp, operation type (upload/download/delete/conflict), file path, success/failure
2. **Persistent storage**: Store dedicated file-operation records in `.syncit/sync-operations.jsonl`; retain `.syncit/log.jsonl` for general structured events
3. **UI access**: View log from sidebar or command
4. **Log rotation**: Keep last 30 days, auto-purge older entries
5. **Size control**: Let users set a maximum log size and rotate/purge safely at that limit
6. **Error details**: Capture full per-file error messages for debugging
7. **Reconciliation decisions**: Record first-sync authority, per-file decisions, tombstones, and manifest commits

## Current Source State

- `src/logging/SyncLogger.ts` already provides JSONL persistence, level filtering, age-based purge, size-based purge, and an optional plugin-directory backup.
- `src/settings.ts` already exposes log level, maximum age, maximum size (default 10 MB), and backup settings.
- `src/main.ts` persists one structured `ERROR` entry for every failed file operation and retains the final summary count.
- Successful per-file uploads, downloads, and deletes are not yet persisted as individual audit records.
- `.obsidian/plugins/obsidian-syncit/debug.log` is an internal diagnostic destination and must remain separate from the user-facing operation history.
- `src/ui/SyncSidebarView.ts` provides separate bounded Activity and Errors viewers with filters, details, and load-more pagination.
- Rotation is purge-in-place, removes malformed/expired lines, trims oldest entries toward 80% of the configured limit, and applies runtime settings safely.
