# T9: Atomic Writes

*Created: 2026-08-17 14:20 IST*

**Status**: 🔄 **IN PROGRESS — atomic text writes implemented**
**Priority**: P1 (User's #6)

## Details

Prevent file corruption if Obsidian crashes mid-sync by writing to temporary files and renaming atomically.

## Goals

1. **Write to temp first**: All file writes go to `.tmp` first
2. **Atomic rename**: On success, rename `.tmp` to final filename
3. **Cleanup on failure**: Delete `.tmp` files if write fails
4. **Local and remote**: Both local vault writes and remote WebDAV writes

## Notes
- Simple but critical for reliability
- WebDAV servers may not support atomic rename — need fallback
- Should be transparent to the rest of the code
- T13 requires atomic replacement for reconciliation transfers and manifest commits so a failed first sync cannot leave a false baseline.
- Binary-safe read/write support must be verified alongside the temporary-write path.

## Implementation Notes (2026-08-18)

- `src/sync/AtomicWrite.ts` provides the shared `.syncit-tmp-*` marker and same-directory temp path generation.
- Local writes use the Obsidian `DataAdapter` directly: `write(temp)`, then `rename(temp, final)`. Failed writes remove the temp path and preserve the original error.
- WebDAV writes use `PUT(temp)`, then `MOVE(temp, final)` with `Overwrite: T`. A server that rejects `MOVE` fails safely; it does not receive an unsafe direct final-path upload.
- Temporary paths are excluded from local and remote file listings so an interrupted write cannot become a normal sync candidate.
- `vitest.config.ts` aliases the external Obsidian runtime to a test-only host stub so the complete suite runs under the project’s normal pnpm test command.
